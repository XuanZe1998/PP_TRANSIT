## 先修应用层（发布门槛）

1. 资金完整性：在与生产同版本的 MySQL 预发布环境验证组织创建的重复请求、并发锁竞争、公司 OWNER/MEMBER、冻结额、账本借贷相等和事务回滚；只使用合成余额，不执行真实资金/支付。修复上线前可临时限制组织创建入口。生产发布前备份并只读盘点历史组织转账，异常逐笔调查，不自动扣回。
2. 卡密/敏感数据：验证匿名及普通用户不能读管理库存和单条明文；列表、日志、错误、缓存均不含明文/密文。主动查看明文必须再次鉴权、只返回授权管理员所请求的单条记录。不要把真实卡密放进测试报告。
3. 账号清理：`DELETE /user/profile` 只处理满足严格零余额、无关联记录等条件的个人账号；订单、账本、备份、审计记录不能为了测试被强制清除。具备可接收验证码的临时邮箱和可审计的清理通道之前，不创建生产测试账户。
4. 前端依赖、管理员会话和 CSP：使用锁定依赖安装、运行单测/构建/CSP 浏览器测试；管理员旧持久令牌从浏览器本地存储移除，重新登录，确认服务端旧令牌过期/轮换。`sessionStorage` 只缩短浏览器持久留存，不能防止同源 XSS 读取；CSP 强制策略必须在预发布与真实页面兼容后独立发布 Nginx。HSTS 延长也应分阶段，不直接添加 `includeSubDomains` 或 preload。
5. 发布后只做只读/合成数据验证：核对 API 鉴权、错误码、卡密不可匿名获取、安全响应头、IP 限速与日志脱敏。不做真实支付/资金操作。保留回滚包和监控窗口。

## 然后盘点 DNS 与邮件

1. 在现有 DNS 管理后台导出完整区域记录、TTL、DNSSEC/DS、注册商锁；核对 A/AAAA/CNAME、MX、SPF/DKIM/DMARC、CAA、验证 TXT、`www`/`api`/邮件及其他子域。私有验证值、源站 IP 和凭据不要提交到仓库。
2. 与邮件服务、OAuth、Webhook、回调、证书续签配置逐项对照；公开解析不是区域导出。得到独立备份和回滚路径后才改权威 NS。无需转移域名注册商。

## 最后分阶段接入代理（尚未执行）

1. Cloudflare 中复核导入的记录。邮件相关记录保持仅 DNS；先用低风险 Web 路径验证，再评估根域和 `api` 的代理。设置 API/授权/卡密/订单响应不缓存，静态哈希资源可缓存；验证上传、SSE/流式响应、WebSocket、Webhook、OAuth 回调和证书续签。不得用真实支付来验证回调。
2. 使用源站有效证书和端到端严格 TLS；**不要在未测试回滚与证书续期前关闭 HTTP/HTTPS 源站通道**。代理正常后仅允许 Cloudflare 的有效来源访问公开 Web 端口，同时保留受控运维/证书通道；定期更新来源网段。
3. **真实客户端 IP 必须先修好再用于限速/审计**：当前 Nginx 将 `$remote_addr` 写到 `X-Real-IP` 和 `X-Forwarded-For`，应用只信任本机 Nginx。如果直接开启代理，`$remote_addr` 会变成边缘节点，用户可能共用限速/IP 审计。仅在源站 Nginx 验证连接对端属于可信 Cloudflare 网段时，才用其客户端 IP 头重写 real IP；不能直接信任公网发来的 `CF-Connecting-IP`/`X-Forwarded-For`。先预发布验证伪造头被拒，再灰度切流量。
4. 比较切换前后 DNS、站点/API 状态、登录、限速、缓存头、流式响应和回调；保留原 NS、DNS 区域与可执行回滚方案。只有监控稳定、邮件及接口正常后才扩大范围。Cloudflare 不替代应用鉴权或卡密加密。
