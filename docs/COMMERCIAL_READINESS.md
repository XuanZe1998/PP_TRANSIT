# 商用就绪审计

更新日期：2026-07-12

## 当前结论

项目已经从“可演示原型”提升为“可以进行真实供应商联调和受控内测”的状态，但仍不能宣称完成生产商用认证。真实支付、正式数据库迁移、多实例限流、容量压测、备份恢复、合规文本和运维告警仍需要上线环境与业务资料才能完成。

## 已完成的关键整改

- 默认拒绝的 Spring Security 权限矩阵；用户、管理员和公开接口分离。
- 注册、登录、注销、过期会话、角色边界和 OAuth Provider 流程具备 HTTP 集成测试。
- OAuth `state` 服务端一次性存储并校验 Provider、有效期和重放；Google 邮箱要求已验证。
- 用户会话、管理员会话、API Key、OAuth 授权码和兑换码只保存 SHA-256 摘要；完整密钥只显示一次。
- 上游渠道密钥使用 AES-256-GCM 加密；API 响应只返回“已配置”和脱敏预览。
- 渠道探测使用内置 Provider Gateway，不再执行用户提交的 Python，也不把密钥放入进程命令行或 URL。
- API 请求先原子预留 Token 配额和余额，成功后按真实或显式标记的估算 usage 结算，失败自动释放预留。
- 免费模型不再被零余额错误阻断；负价格和缺失 usage 的静默免费调用被禁止。
- 余额调账使用数据库原子更新，并强制记录原因和双份账本；普通用户不能直接充值。
- 公开模型目录只展示当前健康、已配置、可路由的模型，并返回输入/输出/缓存价格范围、币种和金额精度。
- Plus 订单保存币种、支付证据、交付证据和时间；未支付订单不能下载收据，商户资料缺失时失败关闭。
- ShopGPT 默认关闭；启用时要求显式 HTTPS 地址和商品 ID，不再使用邮箱作为密码或硬编码外部密钥。
- 提供请求 ID、统一错误结构、健康检查、Prometheus 指标、优雅停机和关键查询索引。
- 前端 OAuth 回调校验、一次性 API Key 展示、真实钱包、金额精度、功能开关和登录深链已经补齐；公开页删除伪价格、伪延迟和伪库存。

## 上线前仍必须完成

1. 用 Flyway 或 Liquibase 版本化迁移替换启动期 `SchemaRepairService`，并在生产数据副本上演练升级和回滚。
2. 接入真实支付服务，通过验签 Webhook 入账；落实退款、拒付、对账、发票和税务流程。
3. 将登录限速与 API RPM 限速迁移到 Redis 或其他共享原子存储，完成多实例一致性和故障降级测试。
4. 增加 SSE 流式响应、Responses/Embeddings/Images/Audio API 或明确从产品承诺中移除这些能力。
5. 增加超时分层、指数退避、熔断、半开恢复、按权重路由和定时健康检查。
6. 将主密钥放入 KMS/Secrets Manager，制定密钥轮换方案；现有 AES 主密钥仍由部署方管理。
7. 将浏览器会话迁移到 HttpOnly/Secure/SameSite Cookie，并配套 CSRF 防护；当前 `localStorage` Bearer Token 仍受 XSS 风险影响。
8. 接入 OpenTelemetry、集中日志、SLO/告警、错误预算、审计导出和敏感信息扫描。
9. 完成 MySQL 真实环境、真实 Provider、支付沙箱、多实例、峰值容量和长时间稳定性测试。
10. 完成数据库备份恢复、灾难恢复演练、数据保留/删除、隐私政策、服务条款和供应商转售授权审查。

## 产品侧优先级

- P0：在每次调用前显示“预计最高费用”，调用后显示“实际费用、Token、是否估算、路由价格是否变化”。
- P0：余额页展示统一币种和 `1 元 = 10000 金额单位`，并提供可下载的逐请求账单。
- P0：模型目录提供可用状态、价格范围、上下文限制、是否支持流式/工具/多模态，不能用营销标签代替真实能力。
- P1：一键复制 SDK 配置时只输出 `YOUR_API_KEY` 占位符，密钥只在用户设备本地填入。
- P1：渠道配置采用向导：选择 Provider、填写 URL/Key、真实探测、选择模型、设置售价、发布。
- P1：错误信息给出请求 ID、可重试性和建议动作，不向用户暴露上游响应正文或内部异常。
- P2：增加预算上限、低余额提醒、模型价格变更通知、团队/项目隔离和细粒度 RBAC。

## 发布门禁

只有在以下条件同时满足后才建议标记“可商用”：全量自动化测试通过、生产数据库迁移演练通过、真实支付和 Provider 沙箱通过、多实例压测达到目标 SLO、备份恢复演练通过、安全与合规审查签字完成。
