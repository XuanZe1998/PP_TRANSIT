# 网关、账单与支付轮询职责整理

本次保留现有接口和业务规则，处理跨业务重复实现及大服务中可独立验证的职责。未改数据库结构、售价、余额预占或结算事务。

## 后端

- `TransitService` 负责鉴权、路由和结算编排；`ChatPayloadPolicy` 负责请求体限制、Token 估算、响应正文规范化和用量校验。纯规则不依赖数据库或 Spring 容器。删除已由 `ApiKeyService` 替代的未使用模型白名单判断及未使用的价格重载。
- `BillingDocumentSettings` 是订阅与充值账单共同的商户、时区、字体配置入口，沿用 `payment.documents.*` 配置键。订单归属、支付证据与金额快照校验仍由各订单服务执行，PDF 排版仍由 `BillingPdfRenderer` 承担。
- 行为收紧：充值账单过去未验证商户配置，现在与订阅账单一样，配置缺失、邮箱或时区非法时返回 503，避免生成不完整单据。不在应用启动时强制要求配置，未启用账单的实例仍可启动。

## 前端

- `createPollingTask` 统一轮询调度。每个目标上一请求完成后再计时；重复启动相同目标不叠加任务；更换目标或销毁后，旧请求通过版本校验失效；失败重试有次数上限。调用方必须在异步请求后检查 `isCurrent()` 再更新界面。
- 订阅发货和充值到账保留各自业务回调，调度器不依赖 Vue、HTTP 或订单状态。页面卸载调用 `dispose()`，异步流程之后也不能重新启动。
- `downloadFile` 统一 Blob 下载、临时 DOM 清理和延迟释放 URL；`getHttpDownloadErrorMessage` 统一解析 Blob 中的服务器错误。订阅与充值均使用这一入口。
- 不改变列表接口或分页参数。订阅支付仍只查询目标订单，完成后刷新当前页，不对历史订单整表轮询。

## 验证与后续边界

新增单元测试覆盖 UTF-8 请求大小、异常用量、推理正文回退、商户配置错误、轮询慢请求、目标切换、销毁与重试上限；继续执行现有网关结算与鉴权集成测试、分页守卫及浏览器支付流程。

## 第二阶段：控制台业务模块

- `features/user-console` 分离钱包、API Key、用量日志的状态与请求逻辑，以及对应展示组件。钱包继续使用统一轮询器；一次性 Key 在关闭弹窗及页面销毁时清空。个人资料复用原有 `ProfileCenter`，不另造实现。
- `features/admin-console` 分离财务、设置和用户调账/企业升级。财务流水与设置数据各自持有状态，不再共用其他管理模块的列表状态；部分财务接口失败仍允许展示成功加载的区域。
- 管理模块的字段配置通过 `createAdminConfigs()` 为每个控制台实例创建，动态修改提供商选项不会污染其他实例。金额与百分比格式化、面板样式集中复用，保留原有 DOM 层次及布局。
- 主页面保留导航、模块选择、通用编辑器和刷新编排；接口、付款门禁、二次确认、默认分页、稳定列表 ID 均沿用原约定。设置页复杂插值改为计算值，使英文翻译能正确替换动态提示。
- 新增测试覆盖财务分区失败与分页参数、用量日志部分失败、设置保存后刷新失败、调账取消/提交、配置实例隔离；浏览器覆盖 Key 一次性展示、钱包/资料导航、调账确认与列表刷新。继续运行全量前端单元测试（含分页守卫）、浏览器回归、翻译检查和生产构建。

网关管理、在线调试和历史数据库修复服务仍有较大的模块。本次没有把历史迁移或兼容路径作为死代码删除，也不宣称完成全仓库重写。后续拆分应逐个按业务域迁移，并保留对应接口与存量数据验证。

## 第三阶段：网关管理职责与异步边界

- `AdminChannelService` 保留渠道配置、模型定价编辑及原有事务边界；`ChannelProbeService` 独立负责探测模型选择、聊天/图像连通性测试、凭据测试、成本估算和健康记录。管理接口仍通过原服务委托，调用方无需迁移。`ChannelModelNames` 统一模型名称解析与校验。
- 探测失败不再将底层异常原文写入响应及测试日志，避免 SDK/网络异常携带凭据；HTTP 状态、超时和探测状态继续保留。
- `features/model-gateway/useGatewayData` 管理服务端筛选、分页和站点/分组选项。列表及汇总结果检查请求版本，退出页面后丢弃响应；选项加载成功后才推进页码，失败重试不跳页。汇总失败仍保留已加载的列表及真实总数。
- `useGatewaySettings` 管理站点展示、分组配置与账号授权，站点身份仍使用站点 ID；关闭或离开页面清理本地 Key、密码及验证码。`useGatewayJobs` 复用统一异步轮询器，按任务 ID 去重，等待上一轮完成后再调度；临时网络失败不会丢失任务，完成任务合并刷新一次，卸载后不再提示或刷新。
- 目录同步继续由 `GatewaySyncJobs` 和现有目录服务执行，保留持久化任务及统一分组锁；价格预览、版本核验及手工售价覆盖继续使用原有定价服务。未修改数据库结构及列表接口。
- 新增行为测试覆盖请求乱序、汇总失败、全部分页回退、选项失败重试、慢轮询、网络恢复、卸载和凭据清理。继续验证网关定价、同步锁、发布、分组删除、分页守卫及浏览器流程。

## 第四阶段：在线调试

- `features/playground/PlaygroundPanel.vue` 独立承载请求、回答和费用三栏；`usePlayground` 负责 Key/模型联动、路由预选和请求生命周期；`response.ts` 负责响应兼容解析与服务端费用展示。
- 保留 `/user/playground` 一次性响应接口，本轮不新增流式协议。请求使用参数快照并拒绝并发重复提交；离开调试页或销毁组件时中止浏览器等待并使旧响应失效。这不保证撤销已经在服务端执行或结算的请求。
- 模型响应与账户刷新失败分别处理，刷新失败不会抹掉成功回答及服务端结算结果；控制台数据加载也校验请求版本和销毁状态。
- 布局、模型权限和服务端计费规则沿用原实现。验证重复提交、路由切换/卸载、旧响应、刷新失败、权限范围与缓存费用解析。
