# 海外公开站点上线清单（运营填写，非法律意见）

本次改造提供展示、配置和保护机制，**没有替运营方编造公司、支付、退款、数据处理事实**。首次启用海外付费前，确定经营主体、首发国家/地区、消费者还是企业客户、支付通道、上游模型提供方和实际数据流向，交由当地法律与税务顾问审核。

## 公开页面与配置

后台「系统配置与报表」的「公开信息填写区」默认折叠，点击标题展开后逐项保存 `legal.*`。系统配置表格以单行省略展示长内容，点击「编辑」可查看完整值；公开接口 `/api/public/legal` 返回展示数据及 `publication_ready`、`missing_fields`。正文按纯文本逐段（换行）输入；不要输入 HTML 或凭据。公开页面：`/terms`、`/privacy`、`/refund`、`/ai-data`、`/subprocessors`、`/cookies`、`/rights`、`/support`、`/security`。页脚常驻公开及用户页面。

| 配置键 | 运营方必须核实的内容 |
| --- | --- |
| `legal.operator`、`legal.registration`、`legal.jurisdiction`、`legal.address`、`legal.contact_email` | **法定实体**、登记编号与地区、真实联系地址及可接收投诉的邮箱；不能填写品牌名或占位文字 |
| `legal.terms` / `legal.terms_en` | 适用范围、账号/API Key、禁止行为、计费、可用性、终止、责任、争议及适用法律 |
| `legal.privacy` / `legal.privacy_en` | 控制者、收集类别与目的/依据、保留期限、接收者、跨境、用户权利与投诉渠道；核对代码和日志的真实行为 |
| `legal.refund` / `legal.refund_en` | 钱包余额、未使用额度、数字服务、取消、付款争议、退款路径与时限；按目标市场核对消费者权利 |
| `legal.ai_data` / `legal.ai_data_en` | API 输入/输出实际流向、上游及地区、留存/训练/日志、脱敏和删除、企业 DPA |
| `legal.rights` / `legal.rights_en` | 查阅、更正、删除、导出、反对等适用权利的请求渠道、身份核验及处理流程 |
| `legal.support` / `legal.support_en` | 客服时间、投诉渠道、订单争议、故障状态和升级方式 |
| `legal.subprocessors` / `legal.subprocessors_en` | 实际子处理方、功能、地区及更新通知；未确认前不要宣称任何供应商承诺 |
| `legal.cookies` / `legal.cookies_en` | 实际使用的必要存储/非必要追踪、目的、期限、第三方与撤回方式 |
| `legal.security` / `legal.security_en` | 经过验证的安全措施、漏洞报告渠道；不承诺未经验证的认证或 SLA |
| `legal.terms_version`、`legal.privacy_version`、`legal.effective_date` | 首次发布或正文更新时改掉默认版本与日期，并同步提升版本，以触发登录用户重新确认并留存版本记录 |
| `commerce.payments_enabled` | 后台「系统配置与报表」的**线上收款总开关**，默认关闭；单独确认开启，只有与 `publication_ready` 同时成立才允许发起新付款。关闭不会撤销已发出的第三方支付链接或回调，应核对待处理订单。 |
| `legal.publication_approved` | 后台「系统配置与报表」上方独立的**政策审核与发布**开关（不在折叠区内）。仅完成真实核对与人工法律审核后，在确认框中显式批准才设为 `true`；默认 `false`。必填项不齐或状态未知时不能批准；即使已批准仍可撤销。该操作不会开启或关闭收款总开关。 |

`publication_ready` 要求真实经营者、地址、注册信息、地区、邮箱，以及中英文条款、隐私、退款、AI 数据、权利、支持正文和明确批准。缺项、审核未通过或收款总开关关闭时，公开页面提示草稿/结账关闭，钱包/商品支付入口及服务订单付款由前后端保护，不能发起新付款。`cookies`、`subprocessors`、`security` 等仅在相关事实确认后发布，不能因页面存在就视为已完成审核。后台有缺项提示。

## 支付与数据的人工核对

- 价格页声明交易币种以订单为准；钱包、成品服务和商品结账展示政策入口并要求确认。服务端在付款发起时复核公开信息状态与当前条款接受记录。发起支付时前端提交当前披露摘要；服务端核对并在 `legal_checkout_acceptances` 中按用户、业务类型、业务 ID、披露 SHA-256、当时的公开正文快照和时间留痕（快照为长文本，需评估存储和保留周期）（不存原始 IP）。
- 审核当前所有支付路径（充值、服务订单、订阅及第三方商品），逐笔核对税费、汇率、续费/取消、收据。现有订阅服务及兑换/外部跳转不应凭此页面自动宣称受同一付款保护。
- 校验上游供应商合同、子处理方与跨境机制；网页文案不能替代 DPA、合同、转移评估或税务登记。
- 加州及其他地区的额外权利/拒绝出售或共享入口依实际业务适用性配置。不要在没有出售/共享的事实时提供误导性承诺。

## Cookie 与追踪

当前前端没有接入第三方分析脚本。仅当部署显式设置 `VITE_ANALYTICS_SCRIPT_URL` 为 HTTPS 脚本 URL 时，才显示同意条并在用户允许后加载；拒绝不加载，页脚可再次打开设置。部署前核对脚本来源、CSP、供应商实际 Cookie、撤回后的清除方式和隐私政策。第三方脚本一旦执行，撤回会刷新页面以阻止后续加载，但第三方 Cookie 的删除仍需按该供应商文档接入；不能把这一基础机制冒充完整的 CMP。若新增其他非必要标签，必须接入同样的先同意后加载机制。

## 发布验收

1. 在测试环境逐一访问九个公开路由（中/英文），核对实际正文、链接、移动端、错误状态。
2. 未配置/未审核时验证付款服务端返回 409；审核完成且用户接受最新版协议后验证付款可继续。
3. 核对注册及协议更新记录，更新条款时提升版本。运行前端构建、相关 Java/Vitest 测试及分页守卫测试。
4. 真正对外投放前由经营主体、法律、财务和安全负责人签字确认；检查支付通道规则及所在地区要求。
