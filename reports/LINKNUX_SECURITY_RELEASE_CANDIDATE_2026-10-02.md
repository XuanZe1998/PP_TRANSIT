# Linknux 安全发布候选与门禁（2026-10-02）

## 基线纠偏

本候选从 `origin/master` 的 `6bdf2c0b` 创建独立工作树，未合入旧工作区 `codex/sync-console-ui-20260924` 的混合改动。旧报告 `reports/LINKNUX_SECURITY_ASSESSMENT_2026-10-02.md` 所述“创建组织复制余额”PoC 是在**落后生产基线 50 次提交的旧分支**上复现的，不能外推为当前生产版本的已证实漏洞。当前基线已有 `WalletBalanceService.lockTransferableBalance`、受条件约束的借记及企业已分配额度保留。直接移植旧分支的候选补丁造成 10 项现有回归测试失败，已从本候选撤销。此纠偏不代表生产财务历史已审计或不存在其他漏洞。

## 候选范围

- 实现了限定零余额、无历史关联的本人密码账号 `DELETE /user/profile`，但 `security.account-deletion.enabled` **默认 false**；未经独立审查不得在生产开启。开启时仍不对有订单、账本、卡密、余额或额外组织的账户进行自动硬删除；成功删除会使按数据库校验的会话失效。无法保证日志、备份或第三方邮件副本的物理删除。
- 前端 Axios 锁定为 `1.20.0`，CI 加入锁文件高危依赖审计；管理员凭据改为标签页 `sessionStorage`，清理旧 `localStorage` 管理员键。此举不替代 XSS 防护或服务器端令牌轮换。
- 增加只对本机 `127.0.0.1`、专用用户名和 `linknux_security_test` 库开放的 MySQL 8 集成测试；上下文初始化前验证数据源，避免误指生产；测试用合成用户、无真实资金或支付。
- 未引入或修改业务列表，无新增分页契约；现有分页守卫仍需通过。

## 生产发布阻断项

1. 代码审查与独立 PR CI；禁止将旧分支脏工作树推送到 `master`，因为 master push 会自动部署。先确认实际生产基线、资金关键路径以及卡密交付权限。
2. 由有权限运维确认生产 MySQL 服务端版本、只读资金历史盘点；隔离环境复验兼容性。生产数据库不得用于合成并发、故障注入或删号测试。`DELETE` 默认关闭；由于历史表可能没有外键，必须审查并发写入／旧会话在删除检查之后重新产生关联行的可能性，配合约束或统一写路径锁后才能考虑开启。
3. 核验数据库和账本备份**可恢复**、发布脚本与回滚演练；核对删号、审计日志和备份的保留/合规政策。没有可收信的专用邮箱及已验证的清理路径，不创建生产临时账户。
4. Nginx 实际配置由有权限运维备份后 `nginx -t` 并分阶段灰度 CSP/HSTS/缓存头，核查静态资源、API 与 SSE；应用流水线不负责 Nginx 或 DNS。Cloudflare 迁移保持独立变更。
5. 上述门禁通过后才受控合并/部署，先只读健康、鉴权和安全响应头烟测，再用明确隔离且可清理的测试账号做认证态 IDOR/越权复测。仍禁止真实资金和支付。

本文件不是“全站安全”认证，也不是上线批准。
